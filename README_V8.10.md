# V8.10 — 355기관 게시판 고정형 모니터링 + Telegram 대기열

## 1. 운영 목표
- 대상: 355개 공공기관, **1행 = 1기관**
- 흐름: 기관 홈페이지 → 공지게시판 → 최근 게시물 → 상세 본문 → 키워드 검색 → Telegram
- 키워드: `설문조사`, `시민참여`, `국민참여` **정확히 3개**
- 제목에 `공모전`이 포함된 게시물은 제외
- GitHub Actions 하루 1회 실행
- PC를 켜둘 필요 없음

## 2. V8.9 실행 결과 반영
V8.9 #2 실행 결과:
- targets: 355
- completed: 167
- no_board: 188
- posts_checked: 852
- new_matches: 61
- telegram_sent: 20
- errors: 0
- elapsed_seconds: 620.8
- timed_out: false

즉, 355기관 전체 실행은 정상 완료되었고 167기관은 게시판을 확인했으며 188기관은 게시판을 찾지 못했습니다.

**주의:** V8.9는 61건을 신규 매칭한 뒤 20건만 Telegram으로 보내고, 나머지 41건까지 `seen`으로 기록하는 구조였기 때문에 V8.9 실행에서 실제 미발송된 41건은 V8.10에서 자동 복구할 수 없습니다. V8.10부터는 이 문제가 발생하지 않습니다.

## 3. V8.10 핵심 개선 — Telegram 대기열
V8.10에서는 `pending.json`을 사용합니다.

예:
- 오늘 신규 매칭 61건
- Telegram 발송 한도 20건
- 오늘: 20건 발송 + 41건 대기
- 다음날 신규 5건 추가 → 총 46건 중 20건 발송 + 26건 대기
- 이후 매일 최대 20건씩 자동 소진

### 중요한 동작
1. 신규 매칭을 `pending.json`에 먼저 저장
2. Telegram으로 최대 20건 발송
3. **성공적으로 발송된 건만** `seen`에 기록
4. 발송하지 못한 건은 `pending.json`에 그대로 유지
5. Telegram 설정 오류나 일시적 전송 실패가 있어도 대기열을 삭제하지 않음

따라서 **매칭된 공지가 20건을 초과해도 유실되지 않습니다.**

## 4. 발송 우선순위
대기열은 다음 순서로 정렬합니다.

1. 제목에서 키워드가 발견된 게시물
2. 본문에서만 발견된 게시물
3. 키워드 순서: `설문조사` → `시민참여` → `국민참여`
4. 기관명/제목/URL 순으로 안정 정렬

## 5. 기존 V8.9 탐지 로직 유지
- 기존 게시판 URL 우선
- 게시판이 없는 기관은 홈페이지에서 게시판을 탐색하고 `state.json`에 캐시
- 제목 우선 검색
- 본문은 노이즈 영역 제거 + 최소 길이 + 문맥 조건으로 엄격 검색
- XMLParsedAsHTMLWarning 억제
- 공모전 제목 제외
- 최근 게시물 15건 확인
- 동시성 20
- 전체 실행 제한 1200초

## 6. 상태 파일
- `state.json`: 확인된 게시판 및 발송 완료(`seen`) 기록
- `pending.json`: Telegram 미발송 대기열
- `monitor_log.json`: 최근 실행 결과와 대기열/발송 내역

## 7. GitHub Secrets
Repository → Settings → Secrets and variables → Actions에 다음 두 개가 필요합니다.
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

## 8. 실행 일정
매일 UTC 00:10 실행 → 한국시간(KST) 09:10입니다.
